# 移动端全栈全链路性能诊断与自动化审计平台（终极技术白皮书 v2.0）

## 1. 项目概述与架构演进 (Project Overview)
本项目旨在基于开源移动测试框架 **Sonic** 进行深度二次开发，打造一个全栈、全链路的前后端协同性能诊断平台。
除了集成 Sonic 的物理底座、**WebView (CRI)** 和 **Flutter (Dart VM)** 的深度监控外，本平台引入了**时钟同步引擎**与**时序数据落盘机制**，实现“测试期实时高频大屏”与“测试后智能审计报告（含异常截图与链路追踪）”的完美闭环。

### 核心技术栈选型 (Tech Stack Matrix)
* **基础底座**：Sonic 开源平台（设备管理、投屏、物理 CPU/内存/FPS 采集）
* **深度探针**：`chrome-remote-interface` (CRI) + JSON-RPC 2.0 (Dart VM)
* **时序与持久化**：后端 InfluxDB/SQLite (存指标) + 本地存储/OSS (存异常截图) + Redis (状态机)
* **前端与报告展现**：Vue 3 + Vite + ECharts (实时 Canvas 滑动窗口) + HTML/PDF 报告导出器

## 2. 核心架构与系统级修正方案 (Core Architecture & Fixes)

为了彻底解决异构时钟、多实例混淆、观测者效应及内存泄漏等隐患，采集架构必须严格遵循以下基准：

### 2.1 全局时钟基准服务 (Time Sync Engine)
* 由于 Native、CRI、DartVM 采集的时间戳各不相同，Agent 启动测试时必须生成一个全局 `Session_Start_Timestamp`。
* 建立各个协议连接时计算 `Time_Offset`。**所有后端转发的数据，必须扣除/相加 Offset，统一转换为标准的 Unix 毫秒绝对时间戳**。

### 2.2 基于 Sonic 的原生底座对接 (Native Base)
* 提取 Sonic 的物理指标数据流（CPU、内存 PSS、FPS），打上全局时间戳后落盘。
* 开放 Sonic 原生截图 API 的调用通道，供阈值告警时触发。

### 2.3 基于 CRI 的 WebView 深度监控与状态机防御
* **精准靶向 (Target Filtering)**：映射 `chrome_devtools_remote` 端口后，必须先请求 `http://127.0.0.1:[Port]/json`，通过正则匹配当前活动的 `type: "page"` 的 Target 进行连接，防止抓错隐藏 SDK。
* **网络状态机与防泄漏**：
    * 监听 `Network.requestWillBeSent` 记录 Hash，5 秒未返回 `responseReceived` 则抛出 Pending 告警。
    * **强制清空机制**：监听 `Page.frameNavigated`。一旦发生页面整体刷新或跳转，**立即清空内存中的 Network HashMap**，销毁历史定时器，防止内存泄漏。
* **异常截图溯源**：当触发 `Network.loadingFailed`、`status >= 400` 或 `Runtime.exceptionThrown` 时，后端立即调用 `client.Page.captureScreenshot()` 截取 Base64 落盘。

### 2.4 Flutter Dart VM 监控与防爆破
* **防遗失保活**：若 `adb logcat` 动态抓取 Observatory 端口失败，通过 `am force-stop` 重启 App 强制暴露端口。
* **观测者效应抑制**：发送 `streamListen(Timeline)` 时，后端必须**强过滤**，仅放行 `category: 'Dart'` 和 `category: 'Embedder'` 事件，剔除 GC 等无效流，防止撑爆内存。

## 3. 测试进行与自动化审计报告 (Dashboard & Reporting)

### 3.1 测试进行中：实时全链路 Dashboard (Real-time Phase)
* **动态 ECharts 矩阵**：前端采用固定容量（如 MAX_POINTS=300）滑动数组策略。展示 Native CPU/内存、CRI DOM/Event 走势，及 Flutter UI/Raster 双线程堆叠图。
* **全链路瀑布流控制台**：页面底部保持滚动更新的 Timeline 列表，将 Native 掉帧、API 告警、H5 报错按绝对时间戳混排显示。

### 3.2 测试结束后：智能诊断审计报告 (Post-Test Report Engine)
后端从数据库拉取 Session 全量数据，生成带详细证物链的静态报告：
* **动态路由链路分解 (Navigation Flow Breakdown)**：将数据按“页面跳转上下文”切割分组（如：`[POST /login] -> HomeDashboard`）。独立统计每个页面的性能均值和 API 耗时分布。
* **性能违规与崩溃详情展板 (Violations & Crash Evidence)**：
    * 左侧展示案发现场截图（H5 截图或 Native 截图）。
    * 右侧详细说明违规原因（如：“DOM 节点数飙升至 4500（阈值 3000）”、“API `/user/init` 收到 500 状态码并引发前端 TypeError”等）。
